# What changed in Poise, 24–28 October, and what the designs need

Read on 28 October from `main` at `77976fd`. The baseline is `a306a94` (24 October), the last commit these mocks and the two PRDs were checked against. Since then 88 pull requests have merged.

Each one was read: its description, its changed files, and, where it touches the interface, the live code and docs. About 35 change what a person sees. The rest are server, test, CI and deploy work with no design impact.

## 2. What the server can now do

PR #599 built most of #562 and closed it on 24 October; its own description is out of date. `GET /api/capabilities` lists ten capabilities:

`held-reasons`, `review-requests`, `approve-merge`, `behavior-pause`, `organization-unfollow`, `behavior-estimates`, `chat-requests`, `handled-log`, `publication-reviews`, `settings-conflict`.

What this means for the mocks:

- **Board's pull request states are real now.** The server now says why a pull request is held: a draft, a conflict, failing checks (named), checks running, changes requested, review required, an open conversation, behind, blocked. So the mock's *checks failing*, *merge conflict* and *draft* can ship as drawn.
- **Overview's answers are real now.** Review requests, approve and merge as you (a merge queue reports *enqueued*, never *merged*), pausing a behavior until a time, stopping following an organization, every open chat request, and the handling log for *Handled today* are all real.
- **Estimates exist for behavior runs only.** The mock's "≈ 2 min left" on chat turns and on the Manager's work has no data yet.
- **The Manager's controls are stored, but not enforced yet.** Rhythm, Stability, Autonomy, scope and pause are saved, with live defaults of Rhythm 5, Balanced and Balanced. They reach every Manager turn as the effective policy. Their enforcement is not delivered, and no interface shows them yet. The plan, deferred issues and escalation reasons are not delivered at all. The mock's defaults (4, Lean to expansion) differ from the live ones.

## 3. New or changed behaviour, by place

### The Manager and the Switchboard

- **The three-pane view.** The owner's layout is the Manager chat on the left, the work table in the middle, and the Switchboard on the right (PRD #563).
  - Work table columns: PR, Ticket, Worker, Status, Conflicts, Open review, Behind main, CI failing, Now, Latest changes.
  - Flags read ☑ for an observed problem, ☐ for observed clear, and ? for missing or stale.
  - The header shows when it was observed and the serving revision. Merged and deployed are kept distinct.
  - A failed refresh keeps the last snapshot, with its age and the error.
  - It exists today only as an offline V2 rehearsal component (`src/views/work-rehearsal-table.ts`); no live page mounts it yet.
- **The Manager is woken when a worker's PR merges**, with the issues it closed and the open issues that depended on them (#589).

### Chat

- **New session** offers Chat, Worker or Manager (#581). The automatic model now comes from the saved Chat default, not a fixed Opus/High (#648).
- **Stalled workers.** A worker turn that ends with unpushed commits, uncommitted changes or a background job still running is flagged as stalled, in the chat list and in its header, with what was left. Poise wakes it once per stall (#587, #619).
- **Queued turns name their step**, such as preparing or restoring the checkout, in the header, the workspace banner and the chat list (#665).
- **A worker stuck repeating the same check is ended**, with a `[Poise]` note in the transcript (#612).
- **Several chats can be deleted at once.** Shift-click selects a range and Cmd- or Ctrl-click toggles one. Delete confirms once with the count. The rows go at once with *Deleting N chats…*, and any failure comes back with its reason (#614, #700).
- **Stop now ends the turn and every process it started** (#569). Turns and prompts survive a Poise update (#585, #595, #642). Neither needs a design change.
- **Each chat is bound to the pull request it opens**, so CI, conflict and review notices reach it (#617, #621).

### Board

- **Held reasons** (§2) make the mock's pull request detail buildable.
- **Your account reviews the automation account's pull requests**, and the automation account reviews yours (#596). That makes the flag for unreviewable PRs that #563 planned moot, though #563 never formally dropped it.
- **Creating an issue finishes as soon as GitHub confirms it** (#606). This matches the mock's lifecycle.

### Observe

- **Behaviors (Swarm) pages its history.** It loads at most 200 runs at a time, with a pager, exact totals and search on the server (#575, #630, #663). The mock's W15, "the newest 50 first, then the whole history", is out of date.
- **Two new steps, Implement issue and Repair PR**, appear among the runs, from the behavior chain (§4).
- **A repository the automation account cannot read is held once**, with an hourly recheck, instead of failing on every sweep. Replays there are refused with the reason (#566).
- **Held reviews retry by themselves** once the provider recovers (#678).
- **Durations read 6s, 8m 30s or 4h**, and an unknown duration is no longer shown as zero (#726).
- **Health is split into liveness and readiness**, and reports the ledger, data freshness for each organization, and quota for each account (#571).

### Overview

- **Two new notices.** `review_requested` and `pr_conflict` are both Needs you, and the mock already shows both.
- **Two new faults.** `ledger_queue_stalled` and `ledger_capture_loss` come from the ledger, and the mock has neither.
- **Analytics.** All tiles appear together. Content that fails shows an error, never zero (#645).

### Settings

- **General → Chats.**
  - The concurrent-turns cap is now shared by chat turns and behavior runs, and background work leaves one slot for turns you send (#576). The mock's *Running at once* wording is wrong.
  - Idle timeout accepts 0, meaning no idle expiry.
- **General → Behavior chain** is new (#728); see §4.
- **Models.** Three slots, and seven places that pick one (§1):
  - Chat and Editor chat;
  - PR review, PR approval and Issue review;
  - Issue implementation and PR repair, which are new.

  Saved configurations stay. The model check runs daily at 07:00 in your time zone.
- **Saving.** Settings saves only the section you edited. A save that would overwrite someone else's change is refused and your drafts stay (#644, #664). This matches the mock's design.
- **Storage.** The storage reading shows failed, partial and stale states, with their age and Retry (#631).
- **Behaviors.** Approve Pull Requests has a Review cap (§1).
- **Accounts.** A provider you never set up raises no sign-in alert (#639).
- **Snippets.** A second built-in, `/worker`, joins `/manager`, and the default `/manager` text is new.
- **Smaller fixes.** Admin's per-person Start, Stop and Restart stay together (#702). Extension removal is confirmed before its row hides (#706). A first snippet saves even before the library has loaded (#704).

### Editor

- **Autosave status is out of the header.** Failures go to notices (#579). The mock's status line under the page is still right, as long as its height never changes.
- **Undo history is capped at 1 MiB per document**, with a one-time note when it is trimmed (#627).

## 4. V2: a new way of working, rehearsed and switched off

V2 lets the behaviors themselves carry an issue all the way to a merge, without a chat (#728, `docs/Behavior-chain.md`): issue review, then implementation, then PR review, then repair, then merge. It was validated in a sandbox on 28 October, where ten real issues reached actual merges. Production execution is off by default.

The classic interface shows it as Settings → General → Behavior chain:

- a switch: *Run the issue-to-merge chain*;
- which issues enter: those with a label (default `poise`), or every open issue in followed organizations;
- the label;
- a list of chains, each issue → PR with its current step or *Merged*, and *Hold new invocations* or *Resume*.

Our design has no place for this yet. A chain is an issue and its pull request moving through behaviors, so it touches Board, Observe → Behaviors, Settings → Behaviors and Overview's *In motion*.

`docs/design/interface/review.json` is our element review, recovered from these mocks and refreshed against `main` of 27 October. It counts 390 rows and 274 live IDs, and lists 25 capabilities added since our inventory. It keeps the mocks' decisions as design history, not as approved removals.

## 6. Decisions needed

1. **The Manager place.** Proposed: it becomes the owner's three-pane view (Manager chat, work table, Switchboard). The Manager's controls then open from its header over the work table, as well as living in Settings → Manager.
2. **Behavior chains.** Superseded by the fuller proposal in `CHAINS.md`: a task as the unit of work, one phase rail and the journal as its timeline, across Board, Overview, Observe and the Manager.
3. **A stalled worker's state.** Proposed: Blocked, with what is left, for example *2 unpushed commits · tests still running*.
4. **Still open from before:** the light theme, the bell (panel or Overview), Behaviors or Runs, and a held pull request shown as Blocked or Waiting.

## 7. PRD #556 is out of date

- **Out of Scope.** It still lists held pull request reasons, review requests, approving and merging as you, pausing until a time, and unfollowing as needing the server. All of them now exist. Only the Manager's enforced controls, the plan and escalations remain.
- **The Switchboard.** "Folds into the Manager's side pane" is superseded by the owner's three-pane view.
- **Models** become slots.
- **New things to cover:** Worker chats, behavior chains, stalled chats, bulk deletion, the two ledger faults, and Swarm's paging.
- **The element review.** It lives in the repository now (`docs/design/interface/review.json`), which partly answers the question of committing the mocks before approval.
